case.py 文件说明
================

一、文件的主要用途
------------------

case.py 使用 KeYmaera X 对一个连续运动系统进行形式化验证。

它的目标不是验证某个固定延迟 d 下的数值样例，而是证明：

对于任意 d > 0，都可以构造一个初始时看起来满足安全条件的状态，
但系统沿微分方程运行到 t = d/2 时，会越过目标位置，从而进入不安全状态。

这个例子揭示的问题是：

只检查 d 时刻的预测状态是否安全，并不能保证从 0 到 d 的整个运动过程都安全。


二、运动系统
------------

程序研究的连续运动方程为：

    p' = v
    v' = a
    a' = 0
    t' = 1

变量含义：

    p：当前位置
    v：当前速度
    a：加速度
    t：时钟
    d：控制或检查延迟

因为 a' = 0，所以在一次连续演化过程中，加速度保持不变。


三、固定物理参数
----------------

程序使用以下固定参数：

    end  = 10    目标位置
    vmax = 4     最大允许速度
    amin = -2    最小允许加速度，即最大制动强度
    amax = 2     最大允许加速度

最大速度对应的制动距离为：

    sb = vmax^2 / (-2 * amin)
       = 4^2 / 4
       = 4

制动条件使用的系数为：

    -2 * amin = 4


四、三个安全条件
----------------

1. phi_p：位置安全条件

    p <= 10

含义是物体不能越过目标位置 10。


2. phi_v：速度安全条件

phi_v 根据物体和终点之间的距离，分成三种情况。

情况一：已经到达或越过终点

    p >= 10 且 v <= 0

此时速度必须为零或朝反方向运动，不能继续向前。

情况二：距离终点至少为 4

    10 - p >= 4 且 v <= 4

离终点较远时，只要求速度不超过最大速度。

情况三：距离终点小于 4

    0 < 10 - p < 4

此时必须满足以下条件之一：

    v <= 0

或者：

    v^2 <= 4 * (10 - p)

第二个不等式是制动安全条件。物体越靠近终点，允许的正向速度越小。


3. phi_a：加速度预测条件

程序假设在未来 d 时间内保持恒定加速度，并预测 d 时刻的状态：

    p(d) = p + v*d + a*d^2/2
    v(d) = v + a*d

phi_a 要求：

    d 时刻的预测位置和速度满足 phi_v；
    -2 <= a <= 2。

这里存在一个关键缺陷：phi_a 只检查 d 时刻，没有检查 0 到 d 之间的状态。


五、参数化反例的构造
--------------------

对于任意 d > 0，程序先定义：

    u = d / (d + 1)

然后构造初始状态：

    p = 10 - u^2/4
    v = u
    a = -2*u/d
    t = 0

把 u 代入加速度，可以得到：

    a = -2 / (d + 1)

因为 d > 0，所以：

    -2 < a < 0

因此构造出的加速度始终位于允许范围 [-2, 2] 内。


六、为什么初始状态满足安全条件
------------------------------

1. 位置安全

初始位置为：

    p = 10 - u^2/4

由于 u > 0，所以 p < 10，因此 phi_p 成立。


2. 速度安全

初始状态距离终点为：

    10 - p = u^2/4

初始速度为：

    v = u

所以：

    v^2 = u^2
        = 4 * (u^2/4)
        = 4 * (10 - p)

它正好位于制动安全条件的边界上，因此 phi_v 成立。


3. d 时刻的预测状态安全

经过完整的 d 时间后，速度为：

    v(d) = v + a*d
         = u + (-2*u/d)*d
         = -u

位置为：

    p(d) = p + u*d + (-2*u/d)*d^2/2
         = p + u*d - u*d
         = p

因此，经过 d 时间后：

    物体回到原来的位置 p；
    速度变成 -u，即开始向后运动。

所以 d 时刻的预测状态满足 phi_v，加速度也在合法范围内，phi_a 成立。


七、为什么系统在 d/2 时不安全
-----------------------------

在中间时刻 t = d/2，速度为：

    v(d/2) = u + (-2*u/d)*(d/2)
           = 0

这表示物体此时到达最远位置并停下，接下来将向后运动。

此时的位置为：

    p(d/2)
      = p + u*d/2 + (-2*u/d)*(d/2)^2/2
      = p + u*d/4
      = 10 - u^2/4 + u*d/4
      = 10 + u*(d-u)/4

对于 d > 0，有：

    u > 0
    d - u > 0

所以：

    p(d/2) > 10

这说明物体在 d/2 时已经越过目标位置，位置安全条件 phi_p 不成立。

整个运动过程可以理解为：

    初始状态安全
        -> 物体向前运动
        -> 在 d/2 时越过终点并停下
        -> 物体开始向后运动
        -> 在 d 时刻回到初始位置

因此，虽然初始状态和 d 时刻的预测状态都看起来安全，但中间过程并不安全。


八、KeYmaera X 验证的两个证明义务
--------------------------------

程序向 KeYmaera X 提交两个证明义务。

1. initial-premise

    CONSTRUCTION -> INITIAL_SAFETY

它验证参数化构造满足：

    phi_p and phi_v and phi_a


2. unsafe-midpoint

    CONSTRUCTION -> <ODE_PROGRAM> MIDPOINT_UNSAFE

尖括号形式 <ODE_PROGRAM> 是微分动态逻辑中的 diamond 模态，表示：

    存在一条符合该连续运动方程的轨迹，可以到达后面的状态。

该证明义务验证系统可以在 t = d/2 到达以下状态：

    p > 10
    v = 0
    not (phi_p and phi_v)

原安全公式通常使用 box 模态，要求所有可能轨迹都安全。
只要能够证明存在一条轨迹到达不安全状态，就构成了对原安全公式的反例。


九、main 函数的执行流程
----------------------

main 函数主要进行以下操作：

1. 从环境变量读取 KeYmaera X 和 Java 配置。
2. 将证明超时时间设置为至少 120 秒。
3. 启用证明文件保留功能。
4. 创建上述两个证明义务。
5. 依次调用 KeYmaera X 检查证明义务。
6. 输出每条公式的证明结果和详细信息。
7. 如果两个结果都是 Verdict.TRUE，程序返回退出码 0。
8. 如果任意一条没有证明成功，程序返回退出码 1。

生成的 .kyx 和 .kyp 证明文件保存在：

    tmp/case-keymaerax-artifacts


十、运行要求
------------

运行命令：

    python case.py

运行前需要按照项目 README 配置 KEYMAERAX_JAR。
Java 可以通过以下方式之一提供：

    KEYMAERAX_JAVA
    JAVA_HOME
    PATH


十一、总结
----------

case.py 证明的是一个“采样时刻安全，但连续过程不安全”的参数化反例。

安全条件只预测并检查 d 时刻的状态。构造出的物体在 d/2 时越过终点，
随后向后运动，并在 d 时刻回到安全位置。因此，单独检查 d 时刻不能保证
整个连续运动区间都满足位置安全条件。
